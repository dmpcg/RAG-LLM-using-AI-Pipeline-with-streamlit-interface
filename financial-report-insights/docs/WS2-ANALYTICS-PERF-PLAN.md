## 3. Work packages

### WP-A — P0-5: AnalysisResults dict-cache (LIVE bug)  *(M, ~2h)*
- **Files:** `structured_types.py`, `financial_analyzer.py`
- **Fix #1 (PRIMARY — kills the live bug, PRD-preferred):** in `analyze()` (`:13794`) stop round-tripping through `to_dict()` to build insights — compute insights from the in-memory result/fields directly, assigning `.insights` BEFORE any `to_dict()` consumer. This alone resolves P0-5.
- **Fix #2 (belt-and-suspenders, recurrence guard):** invalidate `_dict_cache` on `__setattr__` so post-construction mutation is always visible. **Construction-order hazard (OBJ-4, RESOLVED):** `AnalysisResults` is a non-frozen `@dataclass`; the generated `__init__` assigns all 11 fields via `__setattr__` BEFORE `__post_init__` runs, so a naive override would (a) fire on every field assignment during construction and (b) reference `_dict_cache` before `__post_init__` creates it → `AttributeError`. Mandatory implementation: declare `_dict_cache: Any = field(default=None, init=False, repr=False, compare=False)` as a **class-level dataclass field** (so it exists from the first assignment), and have `__setattr__` guard with `if name != '_dict_cache': object.__setattr__(self, '_dict_cache', None)` — invalidate unconditionally on real field writes (no `_initialized` flag needed once `_dict_cache` is a class-level default; the guard only avoids self-recursion on the cache attribute itself). **Also update the in-code contract** at `structured_types.py:182-183` which currently says "mutating fields directly will NOT invalidate this cache" — that comment becomes false and must be corrected, since the change reverses the documented immutability contract other call sites may read.
- **Tests (fresh — none exist):**
  1. **Post-construction mutation** (guards fix #2): construct `AnalysisResults`, read `to_dict()`/`__getitem__` to seed the cache, then mutate `.insights`, assert the new value is visible via dict-style access.
  2. **Original-ordering recurrence test** (WS2-O5 — would FAIL against current `__setattr__`-less class): reproduce the ORIGINAL ordering — call `to_dict()` first, THEN set `.insights` — and assert the dict view shows the new insights. This proves fix #2 works independently of fix #1 (so fix #1 removing the round-trip cannot silently mask whether the invalidation guard is correct).
  3. **`analyze()`-level test**: `result["insights"]` is non-empty when insights were generated.
- **Acceptance:** post-construction mutation visible; original-ordering test passes; analyze() insights populated in dict view; contract comment corrected.

### WP-B — P0-13: IGR uses safe_divide  *(XS, ~0.5h)*
- **File:** `financial_analyzer.py:8855-8859`. Replace hand-rolled guard with `safe_divide(roa_b, 1 - roa_b)` (default None). **Threshold change is INTENTIONAL and NOT byte-equivalent (OBJ-3, RESOLVED — accept):** the current guard returns None when `abs(1 - roa_b) <= 1e-9`; `safe_divide` only returns default when `abs(denominator) < 1e-12` (`:42`). For denominators in the band `[1e-12, 1e-9)` the old code yielded `igr=None`, the new code yields a large finite IGR (up to ~1e9). We **accept** this: a financial growth rate is genuinely defined (if extreme) in that band, and canonicalizing on `safe_divide` is the PRD intent. This is recorded as a deliberate threshold relaxation, not "Risk: none." **Tests:** (1) `1-roa_b` with `abs < 1e-12` → IGR None; (2) **band test pinning the new behavior**: `1-roa_b` in `[1e-12, 1e-9)` → IGR is a large finite number (was None previously); (3) normal denom → unchanged value. Coordinated with WP-F: WP-F does NOT re-touch IGR — see D2.

### WP-C — P1-A1: vectorize detect_anomalies  *(M, ~3h)*
- **File:** `financial_analyzer.py:3500-3564`. Replace per-row loops with numpy boolean masks for both IQR and z-score branches; build outlier list from `series[mask]`. **ddof requirement (OBJ-5/WS2-O4, RESOLVED):** the IQR branch emits `z_score = (value - mean)/std` where `std = series.std() or 1.0` — pandas `Series.std()` defaults to **ddof=1**, whereas `np.std()` defaults to ddof=0. The vectorized path MUST use `np.std(arr, ddof=1)` (or keep computing via the pandas Series) AND preserve the `or 1.0` zero-std fallback, or every emitted `z_score` will differ. **Acceptance scope clarified:** "byte-identical outliers" means the snapshot compares **all** emitted `Anomaly` fields — `metric_name`, `value`, `expected_range`, `z_score`, AND the formatted `description` string — for the identical outlier set/order, not just the index set. **Tests:** equivalence vs a snapshot of the current output on a fixed series (capture BEFORE refactor), across IQR + z-score + edge cases (empty, all-equal/zero-std → `or 1.0` path, NaN); plus a perf assertion (see D6 for measurement method). **Risk:** ddof mismatch (every z_score) and float-edge differences at the threshold boundary — match pandas ddof, use identical comparison operators, snapshot-lock equivalence.

### WP-D — P1-A2: optimize Monte Carlo  *(L, RE-SCOPED ~6h — see D7)*
- **Scope correction (OBJ-2 BLOCKER / WS2-O3, RESOLVED — re-scoped):** the original "compute the scored metric in a vectorized/batched manner" is **rejected as written**. The per-iteration body (`:3872-3884`) does NOT compute one metric — it runs FIVE branchy, None-aware scoring functions (`composite_health_score` weighted-band logic, `altman_z_score`, `piotroski_f_score` a 9-criterion integer accumulator with `safe_divide` None-guards at `:2868-2960`, `calculate_profitability_ratios`, `calculate_liquidity_ratios`) collecting 6 metrics. Faithfully re-implementing all five in parallel numpy is a major reimplementation (well beyond a 5h task) and is precisely where integer-score-boundary / band-edge / None-handling equivalence would silently drift — a behavior change WS-2 forbids. **Therefore WS-2 does NOT vectorize the scoring functions.**
- **In-scope optimization (bounded, no scoring re-implementation):** (1) cache `dataclasses.fields()` / the assumptions-key list ONCE outside the loop instead of recomputing per iteration; (2) **vectorize ONLY the RNG draw** — pre-generate all parameter samples in one `rng.normal(loc, scale, size=(n_sim, k))` call, apply the `max(x, 0.001)` floor as a vectorized `np.maximum`; (3) hoist `_apply_adjustments` allocation overhead where it does not change the scored result. The five scoring calls stay per-iteration (looped over pre-drawn rows). Preserve the 10k cap and the percentile outputs.
- **RNG-stream-order break (WS2-O3, ACKNOWLEDGED):** moving from per-field `rng.normal` calls in dict-iteration order (`:3865-3868`) to a single batched `rng.normal(size=(n,k))` draw consumes the RNG stream in a DIFFERENT order, so the SAME seed yields DIFFERENT samples. **Exact (byte) seed reproducibility is intentionally lost.** If exact reproducibility is required by any caller, the batched draw MUST replicate the original draw order (one column at a time in the same field order) — preferred, and it preserves seed-exactness. The plan mandates the **draw-order-preserving** batched form so the seeded test can remain exact; only if that is infeasible do we fall back to statistical-only equivalence.
- **Tests (target the ACTUAL outputs — WS2-O2):** the implementation computes **p10/p25/p50/p75/p90/mean/std** — there is NO P5/P95. Equivalence test asserts **mean, p10, p50, p90** (and ideally exact match under draw-order-preserving RNG). **Concrete tolerance (WS2-O3):** if draw order is preserved → assert exact equality (seeded, deterministic). If draw order is NOT preserved → relative tolerance `rtol=2e-2` on mean/p10/p50/p90 over `n_sim=10000`, fixed seed, single rep. **Perf:** see D6 for measurement method (no bare wall-clock assert).
- **Acceptance:** scoring functions unchanged (no numpy re-impl); RNG draw + field-cache optimized; equivalence test green at the stated tolerance; perf demonstrated per D6.

### WP-E — P1-A4: /compare quick-return  *(S, ~1h)*
- **Guard condition CORRECTED (OBJ-1 MAJOR / WS2-O1, RESOLVED):** the original "when deltas AND period_data are both empty, bail" is a **correctness regression** and is unreachable as a useful signal. At the decision point (`api.py:504-509`), `period_data = getattr(rag, '_period_financial_data', {})` is empty on EVERY fresh request because it is lazily computed; the very call we want to skip (`_get_financial_analysis_context()`, `app_local.py:198`) is what POPULATES it (`:258-259`). Bailing on "period_data empty" would return EMPTY deltas even when documents ARE loaded and contain valid data — exactly the behavior the plan forbids. There is also no way to know period_data is empty WITHOUT first running the scan. The correct, cheap, pre-scan signal is **"no documents ingested at all"** — `not getattr(rag, 'documents', None)` (`app_local.py:104`). Note also `_get_financial_analysis_context()` has a fast-path cache (`:207-210`) so the "expensive pass" is only cold on the first request; the quick-return's value is avoiding the cold first scan when there is provably nothing to analyze.
- **Revised fix:** in `/compare`, BEFORE the `_get_financial_analysis_context()` call, if `not deltas` AND `not rag.documents`, return an empty `CompareResponse` immediately. When documents ARE loaded, behavior is unchanged (the lazy scan still runs and populates period_data).
- **Tests:** (1) **no documents ingested** → fast empty `CompareResponse`, `_get_financial_analysis_context` NOT invoked (assert via mock/spy on `rag.documents == []`); (2) **documents ingested, context not yet computed** (`rag.documents` non-empty, `_period_financial_data` empty) → the scan IS invoked and deltas are produced (this is the regression-guard the original spec would have failed). **Acceptance:** no-documents path skips the scan; document-loaded path is byte-unchanged.

### WP-G — P1-A5: FAISS IVF retrain on power-of-two  *(S, ~2h)*
- **File:** `vector_index.py:317-325`. Past `_IVF_THRESHOLD`, only rebuild the IVF index when the new total crosses a power-of-two boundary (else just add to the existing index). **Recall is a SEMANTIC change, not just perf (OBJ-7, RESOLVED — measure don't assume):** between power-of-two boundaries, vectors are inserted into an index whose centroids were trained on a strictly older/smaller set; boundaries become exponentially sparse (16384→32768 = 16k vectors added with no retrain), so recall can degrade progressively. The plan no longer hand-waves "acceptable (IVF is approximate)". **Replace the unmeasured "search results remain correct" criterion with a measured recall floor:** add a test that, after staggered adds spanning at least one full power-of-two gap, measures recall@10 of the lazy-retrain index against the full-rebuild-every-add baseline on a fixed synthetic set, and asserts **recall@10 ≥ 0.95** (tunable; pin the number once measured). If recall falls below the floor, narrow the retrain cadence (e.g. every 1.5× growth instead of power-of-two) — this keeps the WP within "no behavior regression". **Tests:** (1) adds past 10k trigger rebuild ONLY at power-of-two boundaries (count rebuilds via spy); (2) recall@10 floor test above. **Acceptance:** no per-add retrain; measured recall@10 ≥ floor vs full-rebuild baseline.

Mark the absolute-threshold variants (`<1s`, `<5s`) as **non-gating benchmark output** (printed/logged), not assertions. The relative assert is the gate.
